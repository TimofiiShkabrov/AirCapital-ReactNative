# План развития AirCapital

Цель: надёжный международный монитор депозитов на криптобиржах с понятной статистикой роста и уменьшения. Объём текущей работы — аудит, концепция, прототип и план. Изменения production-кода, подключение реальных ключей, публикация и оплата в этот этап не входят.

## 1. Что сохранить и убрать

Сохранить и переработать: пять существующих адаптеров, аккаунты, безопасное хранение ключей, сводный баланс, историю снимков, детализацию кошельков, чтение позиций, RU/EN. Не переписывать приложение целиком ради визуального обновления.

Убрать: маршрут и интерфейс терминала; запросы выставления/отмены ордеров, закрытия позиций, изменения плеча и режима; связанные trading-only типы, состояние, зависимости и инструкции Read + Trade. Из общего Bybit-модуля аккуратно выделить чтение. История исполнений нужна для аналитики и остаётся.

Миграция: объяснить замену старых ключей на read-only; архивировать существующие grid-планы; предупредить затронутых пользователей, что выставленные на бирже ордера продолжают существовать. Никаких автоматических отмен или закрытий. Проверить deep links и восстановление старого состояния. Удаление кнопки терминала не завершает миграцию.

Не добавлять домашнюю бухгалтерию, банковские счета, планировщик расходов, торговые сигналы и налоговые декларации в MVP.

## 2. Порядок разработки

Оценки предварительные: для одного опытного React Native/TypeScript-разработчика с отдельной помощью QA/дизайна. Они не являются сроком обязательства; уточнить после первой итерации и проверки ответов всех бирж.

| Этап | Оценка | Результат | Приёмка |
|---|---|---|---|
| 0. Зафиксировать модель данных | 2–3 дня | Карта кошельков пяти бирж, определение общего депозита, fixtures и перечень операций записи | Для каждого поля известны единица, источник, смысл и риск двойного учёта |
| 1. Достоверность и ключи | 1–2 недели | D-01…D-06 и S-02 исправлены; статусы свежести; гарантированное завершение загрузки | Повторный импорт не меняет сумму; полный вывод даёт ноль; ошибка не создаёт новый успешный снимок; удаление ключей подтверждено |
| 2. Удаление торговли и новый основной интерфейс | 1–2 недели | Обзор, Биржи, Статистика; подключение read-only; миграция старых пользователей | Из приложения нельзя отправить торговую команду; суммы и фильтры согласованы; старые ссылки безопасно обработаны |
| 3. История и объяснение изменений | 2–3 недели | Пополнения/выводы, собственные переводы, вклад аккаунтов, сравнение периодов, экспорт | Все итоговые разницы сверяются; неполная история явно обозначена; фильтр корректно меняет границу портфеля |
| 4. Защита, локализация и закрытая бета | 1–2 недели | Локальная защита истории, блокировка/превью, RU/EN, RTL, совместимые обновления зависимостей, native QA | Отказ/восстановление/удаление проверены; крупный шрифт и экранный диктор работают; оставшиеся риски разобраны |
| 5. Платная бета | 1–2 недели | Проверенный тариф, подписка и восстановление, доступ к Pro-функциям, поддержка | Ошибки покупки и возвраты не теряют данные; тариф не скрывает состояние подключения или возможность удаления |

Итого ориентир 7–12 недель плюс подготовка. История API, миграции и внешнее тестирование могут расширить срок. Серверный мониторинг 24/7 — отдельная оценка после беты, не скрытая часть этого срока. Реальная точность балансов важнее календарного обещания.

## 3. Архитектура

### Разделить текущий portfolioStore

- **Адаптеры бирж:** подпись, безопасный транспорт, проверка envelope/schema, лимиты, пагинация и нормализация. Только разрешённые операции чтения. HTTP-метод сам по себе не доказывает безопасность — проверять смысл endpoint.
- **Домен расчётов:** количественные значения и валюты, оценка активов, equity, потоки, сопоставление переводов, периодические итоги. Без строк интерфейса и React.
- **Хранение:** аккаунты, ссылки на секреты, снимки, события, миграции и атомарная запись результатов. Секреты отдельно от экспортируемых данных.
- **Координатор обновления:** дедупликация запусков, ограничение запросов, timeout/cancellation, backoff для чтения, статусы по категориям, запись только подтверждённых наблюдений.
- **Представление:** форматирование чисел/дат, локализация, выбор периода/биржи, доступность и пользовательские сообщения.

Не добавлять глобальный backend только ради графика. Сначала надёжный локальный монитор с явными ограничениями фонового обновления.

### Минимальные сущности

| Сущность | Существенные поля |
|---|---|
| ExchangeAccount | id, exchange, название аккаунта, тип/регион endpoint, secretRef, проверенные возможности |
| BalanceObservation | accountId, walletType, asset, quantity, debt/equity semantics, observedAt, receivedAt, source |
| Valuation | quoteCurrency, price, priceAt, источник курса, признак отсутствующей цены |
| Snapshot | набор наблюдений, итог, coverage, lastSuccessAt, complete/partial/stale, версия расчёта |
| FlowEvent | стабильный sourceId, accountId, тип, актив/количество, комиссия, время, transferMatchId |
| PeriodResult | границы периода, выбранные аккаунты, начало/конец, потоки, разница, полнота |
| SyncStatus | аккаунт/категория, lastAttemptAt, lastSuccessAt, ошибка без секретов, доступная глубина истории |

Денежные значения хранить как decimal/целые минимальные единицы с точностью инструмента. Не суммировать display-строки и не округлять каждое слагаемое до отображения. Все изменения схемы — с версией и тестом миграции на копии старых данных.

### Покрытие биржи — это матрица

Для Binance, Bybit, BingX, OKX и Gate.io отдельно проверить Spot, Funding, Futures/Unified, Earn и обязательства. Для каждого отметить: баланс, оценка, события, глубина истории, пагинация, permissions, региональный endpoint, лимиты. Наличие файла адаптера ещё не означает полноту поддержки.

Критические примеры: Earn не дублируется с Unified equity; номинал позиции не считается средствами; BTC-only Funding оценивается или явно помечается неполным; отсутствующая цена не превращается в ноль. В UI показывать только реально подтверждённые возможности.

## 4. Статистика по этапам

**Первая версия:** общий депозит и баланс каждой биржи/аккаунта; изменение в USDT и процентах; 24 часа/7 дней/30 дней/свой период; история снимков; состав суммы; время успешного обновления. Процент изменения баланса не подписывать «доходность».

**Следующая версия:** внешние пополнения/выводы, парные внутренние переводы, результат без потоков, сравнение предыдущего периода, вклад каждого аккаунта. Для неизвестных начальных остатков/потоков — честное «недостаточно данных» и импорт подтверждаемой истории.

**После подтверждения спроса:** календарь изменений, группы аккаунтов, разбор комиссий и funding, раздельные реализованный/нереализованный результаты при полной истории, экспорт отчётов, уведомления. Просадку по сырому балансу не выдавать за инвестиционную просадку: вывод средств искажает её.

Рыночные новости, NFT/DeFi-расширения и сотни интеграций не являются условием запуска. Новые биржи добавлять по спросу и только с тестами покрытия.

## 5. Безопасность

До платной беты: надёжное сохранение/удаление секретов, ключи только для чтения с проверкой прав где возможно, системная блокировка, защищённое локальное хранение финансовой истории, скрытие сумм/фонового превью, redaction ошибок и логов, безопасный экспорт без ключей, обновление достижимых уязвимых зависимостей и native-проверка.

При добавлении облака: отдельное согласие, минимальные read-only полномочия, изоляция пользователей, шифрование секретов с управлением ключами, отзыв и удаление, аудит доступа, ограничение запросов, защита платёжных webhook. Сервер, который обращается к бирже с ключом и читает баланс, получает доступ к этим данным; нельзя одновременно обещать, что он никогда их не видит. Зашифрованный backup и серверный импорт — разные режимы.

Подробные подтверждённые проблемы и критерии исправлений: [технический аудит](./technical-audit.md). Внешний аудит готового релиза планируется отдельно; текущая проверка его не заменяет.

## 6. Проверки

Сохранённые [7 воспроизведений](./reproductions.test.ts) фиксируют ошибочное текущее поведение. При исправлении соответствующее ожидание заменить на правильный результат; проходящий сегодня probe не означает, что проблема устранена.

Обязательные сценарии:

1. 100 повторных одинаковых ответов не меняют итог; закрытые Earn-позиции исчезают.
2. Настоящий ноль/отрицательная equity сохраняются; 401/429/500, неверный envelope и timeout не дают ложный ноль или вечную загрузку.
3. Два аккаунта одной биржи не перезаписывают друг друга; двойной тап и частичное удаление не оставляют бесхозных секретов.
4. Перевод между собственными биржами не меняет совокупный результат, кроме комиссии; при фильтре на одну биржу поток учитывается в её границах.
5. Начало 45 000, конец 48 620, пополнения 2500, выводы 500 дают изменение 3620 и результат без потоков 1620. Нельзя маркировать 8,04% как доходность.
6. Актив без цены, отсутствующая категория и устаревший источник явно помечаются; разные единицы USD/USDT не смешиваются без курса.
7. Торговые пути отсутствуют в графе вызовов и deep links; старые планы безопасно мигрируют.
8. На iOS/Android проверены фон, потеря сети, часовой пояс/летнее время, большой шрифт, VoiceOver/TalkBack, RU/EN и RTL.

Для сравнения с конкурентами использовать одинаковые разрешённые read-only аккаунты или синтетические импортируемые наборы. Сейчас реальных ключей и платных конкурентных аккаунтов в проверке не было.

## 7. Результат текущего этапа

Подготовлены аудит с доказательствами, концепция с конкурентным сравнением, интерактивный прототип монитора депозитов и этот план. Код работающего приложения не изменён. Следующий конкретный пакет реализации: этап 0–1, затем удаление терминала и перенос проверенного дизайна в React Native.
