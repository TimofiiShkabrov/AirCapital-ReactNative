# Быстрое подключение бирж: оценка для AirCapital

Проверено 2026-09-06. Рабочие автоматические подключения не добавлены: нет зарегистрированного приложения/разрешений бирж. Ручное подключение и официальные инструкции доступны в приложении (`/connect-guide`). Заявки и сообщения биржам не отправлялись.

## Что делает Veles

[Veles для OKX](https://help.veles.finance/ru/exchange/okx/connect/) описывает подтверждение через страницу биржи для основных аккаунтов; субаккаунты подключаются вручную. В их ручном сценарии запрашивается торговое разрешение. Для AirCapital нужен отдельный профиль доступа только к просмотру.

## Реальные варианты

| Биржа | Публично подтверждённая возможность | Что требуется AirCapital |
|---|---|---|
| OKX | OAuth Connect, scope `read_only`, PKCE для приложений без сервера. Scope не включает модули субаккаунтов. Fast API описан отдельно и создаёт ключ с read + trade | Заявка OKX Connect; одобрение приложения и client_id; документация endpoints/redirect URI от OKX; подтверждение доступа к нашим balance endpoints. Приоритетный кандидат |
| Bybit | Broker OAuth: после согласования выдаются client_id/secret; code обменивается на token, затем получаются API key/secret | Согласование через Broker Program; подтверждение read-only и нужных wallet/Earn permissions. Публичный flow требует client_secret: хранить на доверенном сервере, не в mobile bundle |
| Binance | Fast API / OAuth через Link Program | Корпоративный аккаунт, KYB и проверка безопасности OAuth, зарегистрированные callback/scopes; отдельно подтвердить профиль только чтения и доступ к балансам |
| BingX | Подтверждены создание ключей вручную и read permissions | Общедоступный проверенный OAuth-flow для нашего сценария в просмотренных материалах не найден. Не объявлять отсутствие партнёрских возможностей; запросить условия при необходимости |
| Gate | Broker API умеет работать с ключами управляемых аккаунтов | Это не доказательство OAuth-подключения любого существующего аккаунта. Требуется подтверждение партнёрского сценария; пока ручные API v4 keys |

Источники: [OKX Connect](https://app.okx.com/docs-v5/connect_en/), [Bybit OAuth](https://bybit-exchange.github.io/docs/v5/broker/api-broker/guidance), [Binance Fast API](https://www.binance.com/en/support/faq/detail/6aa7e2253c544d91b60746bfd03fd75d), [Gate Broker](https://www.gate.com/docs/broker-api/broker/en/index.html), [BingX API Management](https://bingx.com/en/account/api/).

## Предлагаемая реализация: сначала OKX OAuth PKCE

1. Согласовать AirCapital как монитор балансов с `read_only`; получить client_id, точные endpoints и разрешённые callbacks для нужных регионов. Не использовать чужие client_id, redirect URI или IP.
2. Модель подключения: `api-key` либо `oauth`; секреты и токены в SecureStore. OAuth-провайдер отделить от GET-транспорта данных: token endpoint требует POST, это не торговый запрос.
3. Авторизацию открывать системной auth-сессией на домене биржи. PKCE S256, случайный одноразовый state, короткий срок незавершённой сессии, точная проверка callback/state и scope. Пароль биржи не вводится в AirCapital.
4. Проверить фактически выданные права до чтения данных; разрешить только read_only. Большее разрешение не принимать. Закрепить идентификатор биржевого аккаунта, чтобы переподключение другого пользователя не смешало истории.
5. Реализовать Bearer/TERMID согласно подтверждённой схеме OKX; обновление токенов с сериализацией, атомарным сохранением и корректной обработкой отзыва/истечения. Поведение ревокации взять из полученной документации.
6. Проверить успешный вход, отказ, неверный state, повтор callback, прерывание приложения, истечение и отзыв токенов, отсутствие нужного scope, региональный домен и сохранение истории.

PKCE у OKX позволяет рассмотреть реализацию без нашего сервера. Это не означает, что такой же режим доступен у всех остальных бирж. Сейчас архитектуру и credentials не подменяем заглушками; кнопку «Подключить в один клик» показываем только после появления рабочего одобренного flow.
